# Tournament mode of the trainer (MTT 60 players) — state 2026-09-09

The tournament mode of the 6-max/multiway trainer (`Poker Trainer.bat` → `/training`, start-screen button
**Turnier**). An MTT with **60 players at 6 tables of 10 seats**; the human sits at the **hero table**
(fully played: engine `pokerbot/engine/table.py`, league bots, UI, advisor), the 5 side tables are played by the
**MTT director** (`pokerbot/arena/mtt.py`) fully automatically — **one hand per side table per hero hand**
(same tournament clock). No Prince takeover (pargate6-refuted, `TRAINER_WIRING.md`), reads OFF
as in GTO mode.

## Structure (constants in `pokerbot/arena/mtt.py`)

| Constant | Value | Why |
|---|---|---|
| `N_PLAYERS` / `SEATS_PER_TABLE` | 60 / 10 | product-owner specification; 6 tables |
| `START_STACK` | 5000 = 100 BB at 25/50 | specification |
| `MTT_LEVELS` | 10 levels 25/50 → 800/1600, **ante from level 3** (≈ BB/8 like the PS $1050 structure, `data/ps_tourney_field.json`: 0.13·BB) | specification |
| `HANDS_PER_LEVEL` | 12 (configurable `MTT(hands_per_level=…)`) | levels per hands, not minutes (sim convention from `strategy/tournament.py`) |
| `LEVEL_EXTENSION_FACTOR` | 1.5 | after level 10 the BB keeps growing → termination guarantee |
| `PAYOUT_PCT_TOP9` | 27.8/18.9/13.3/10/7.8/6.7/5.6/5/4.9 % | specification 25/17/12/9/7/6/5/4.5/4.5 (= 90 %) normalized to 100 %; `payouts()` puts the rounding remainder on place 1 → sum EXACTLY the pool (`BUYIN` 10 × 60 = 600) |
| `EXACT_ICM_AT` | 12 | from here on the Malmuth-Harville bitmask DP (2^n) is exactly affordable (`research/mtt_sim.py`) |
| `BUBBLE_WINDOW_FACTOR` / `PRESSURE_CAP` / `PRESSURE_SLOPE` | 1.6 / 1.5 / 0.6 | money-bubble window 9 < left ≤ 14: only the pressure multiplier (mtt_sim constants) |
| `ICM_HINT_BF` | 1.15 | the advisor shows the ICM hint only from this bubble factor on |

**Director mechanics** (taken over from `research/mtt_sim.py` + `Director` in `strategy/tournament.py`):
elimination at 0 chips (no rebuy), **global place assignment** per round (simultaneous busts: larger
starting stack places higher — Sklansky rule), **table collapse** to ⌈alive/10⌉ tables (the smallest table is
dissolved, players go to the shortest tables), **balancing to ±1** (movement only from a difference ≥ 2), final
table at ≤ 10 players, then down to heads-up. If the hero moves, the UI reports "Tischwechsel" (the hero always sits
on seat 0 — the seat order is preserved by rotation). The button travels over names.
**Determinism:** one tournament seed (`/api/new_session {seed}`) controls the seat draw, profile distribution,
every bot RNG (`SixMaxBot(seed=…)`) and every deck (seed per table uid + table hand number).

## Population (`FIELD_MIX`, a PRIOR — not a measured fit)

station 30 % · tag 22 % · lag 15 % · nit 12 % · rock 8 % · whale 5 % · maniac 4 % · shark 4 % (league profiles
from `pokerbot/arena/sixmax.py`; largest-remainder rounding to 59 seats, `field_counts`). Rationale: the mined
PS $1050 pool (`data/ps_tourney_field.json`, 2,055 hands; deep phase VPIP 31.7 / PFR 20.4 / 3bet 10.2 /
FoldVsRaise 53.6 %) is loose-passive (VPIP−PFR gap 11 pp) → stations+whales 35 %, regs core 61 %, maniacs
rare. The measured forced tightness under pressure (FoldVsRaise 54→62 %, jam 1.1→13.1 % short) is generated by the
bots themselves: from ≤ 12 remaining ALL bots get `obs['icm']` (exact stacks + remaining payouts →
`tournament.icm_scaled_req`, proportional risk premium = the μ-3-validated layer), in the bubble window only
the pressure multiplier; before that chip EV. Profiles carry avatars (`AVATARS`: 🐟 station, 🎯 tag, 🔥 lag,
🧊 nit, 🗿 rock, 🐳 whale, 🃏 maniac, 🦈 shark) — the UI shows them at the seat.

## Advisor logic (`six_server.Session._tournament_advise`)

After every hero action: spot record (`coach/decision_log.capture_decision`) → reference oracle →
`oracle.oracle_diff` (verb comparison, bet/raise normalized):
* Table multiway: `SixMaxOracle` (tag core, reads empty, per-spot RNG) — the same reference as the grader.
* Tournament heads-up (`table.n == 2`): `PrinceOracle(stack=auslese.FINAL_STACK, kanal='live')`.
* Verdict: **"GTO ✓"** or **"Abweichung: <action> [<bb>] — <rationale.reasoning>"**.
* **ICM hint** (computed before the action, `MTT.hero_icm`): only if the exact computation is affordable
  (≤ 12 remaining) and BF > 1.15 against the relevant opponent (`pick_villain`: aggressor, otherwise cover stack):
  facing bet → "ICM: call needs +X pp equity (r' instead of r; bubble factor b vs name)" via
  `icm_scaled_req` (all-in calls exact, otherwise proportional premium); otherwise the flip anchor.
* Summary statistics: decisions, GTO rate (HUD + result), top-3 deviations — **rank = pot in bb**
  (proxy for cost; an EV loss per decision is not cheaply available without a solver — limit).
* The existing end-of-hand grading (`_grade_and_flush`, feedback panel) keeps running unchanged.

## API

* `POST /api/new_session {mode:'tournament', seed?, step:true}` — seed optional (None = random).
* `POST /api/action`, `/api/step`, `/api/hand`, `GET /api/state` unchanged; `view()` additionally delivers
  **`tournament`**: `level, sb, bb, ante, players_left, n_entries, rank, hero_stack_bb, avg_stack_bb,
  next_payout{place,amount}, hands_to_level, round_no, table_no, tables, final_table, table_change
  (once), finished, place, payout, prize_pool, payouts[], side_ms, avatars{name→emoji},
  advisor{last{text,match,oracle,human,street,hand_no,icm}, stats{decisions,gto,gto_quote,top_deviations}}`.
* After `finished`, `/api/hand` delivers no new hand (hero eliminated = place + payout, or victory);
  UI: result overlay + "Turnier neu". All in the session — no server restart.

## Addendum (2026-09-09, user QA) — the hand-continuity bug

**User's finding:** "always 100 bb per player", "always played well", once an empty table.
**Cause (reproduced via TestClient):** every tournament hand is a fresh `Table` (hand_no 0 → 1);
`_log_if_done` checks `t.hand_no != logged_hand` and therefore held EVERY hand after the first to be already logged →
no stack return to the field (`after_table_hand`), no busts, no tournament clock, no new feedback: all
hands started again from the stacks after hand 1, the banner showed the hand-1 verdict. **Fix:** the new table
takes over the hand number of the old one (`_tournament_prepare`). **Regression:** `test_hand_continuity` (3 hands:
hand_no/hands_done/logged_hand advance, feedback belongs to the current hand, hero stack flows back, clock +3).
**Re-measurement:** two full tournaments via TestClient (seeds 3/11, random hero): hands 6 and 31 resp., feedback follows
the hand, busts/place correct (place = remaining at bust time), verdicts mixed (seed 11: 38 GTO ✓ /
41 deviation); browser fast run over >3 tournaments, 3,671 renders: 0 empty tables, 0 console errors.
**Empty table — FOUND + FIXED (second user screenshot: "Hand #undefined · Pot NaNbb", net "NaN"):**
tournament blinds are 50/75/150 … chips; the quarter-bb grid of the bet slider then yields e.g. 3.75 bb =
187.5 chips → `ActionReq.amount: int` → FastAPI 422 `{"detail": …}` → the response had no `error` key
→ the client rendered it as game state: seats removed, `v.seats.forEach` threw, board stayed. In the
cash trainer (bb 100, grid 25) this never occurred. **Fix (3 layers):** server `amount: float` + rounding to
whole chips; client `api()` turns every non-OK/non-state response into `{error}`; `render()` never renders
without `seats`; `send()` rounds the amount. Regression `test_fractional_amount_is_rounded` (212.5 → 212, response
is a state); browser: provoked 422 → error line, 10 seats remain; 112.5 chips → 113 set.
**Observation field tempo:** 60 → ~30 players in ~25 rounds (maniacs/whales go all-in early at 100 bb) — for
a training session practical (money in ~30–50 hands), but faster than a real online MTT.

## Limits

* ICM exact only from ≤ 12 remaining; before that only the bubble-window heuristic pressure field, no BF hint
  (with 60 players the money bubble lies at 10 → covered exactly).
* Top-3 deviations by pot size, not by EV loss; the reference is the tag core (85.9 % GTO score
  in the Analyzer), not a solver.
* The level clock counts hero hands; side tables play one hand synchronously — no time levels, no dead button.
* The field mix is a reasoned prior; a calibration to measured bot VPIP/FvR per profile is pending.
